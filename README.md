# TradeLog · 交易记录与复盘

使用 Node.js + Vue 构建的本地交易记录系统，可直接解析项目根目录中的 MT5 历史报告，将交易、资金流水和个人复盘保存到 SQLite。

## 启动

需要 **Node.js 22.13.0 或更高版本**，建议使用 Node.js 22 的最新补丁版本。项目使用 Node.js 内置的 `node:sqlite`，无需单独安装数据库，也不需要 Python。

在项目根目录运行：

```powershell
npm install
npm run dev
```

打开 [http://127.0.0.1:5173](http://127.0.0.1:5173)。此命令同时启动 Vue 开发页面和端口为 `3001` 的 API 服务，修改源码后自动更新。

如果 `5173` 已被其他项目占用，Vite 会自动选择下一个可用端口，请打开终端显示的 `Local` 地址。后端固定使用 `3001`，启动前请先停止本项目已运行的服务，避免重复占用。

后端启动时会自动扫描项目根目录中的 `.html`、`.htm` 和 `.xlsx` 报告。当前目录自带的两份 MT5 报告会自动导入，并按同一账户的持仓标识去重。

### 构建后运行

```powershell
npm run build
npm start
```

打开 [http://127.0.0.1:3001](http://127.0.0.1:3001)。构建后的前端和 API 由同一个 Node.js 服务提供。首次使用前需要先执行 `npm install`；修改前端后需要重新构建。

服务默认只监听本机 `127.0.0.1`。在启动终端按 `Ctrl+C` 停止服务。出现 SQLite 的 `ExperimentalWarning` 是 Node.js 22 对内置 SQLite 的提示，不代表启动失败。

## 使用方式

| 页面 | 功能 |
| --- | --- |
| 交易概览 | 查看净盈亏、胜率、盈利因子、最大回撤、累计盈亏曲线和近期交易 |
| 交易记录 | 按账户、日期、品种、方向、盈亏筛选，搜索交易编号与复盘内容，分页查看 |
| 盈亏日历 | 查看每天的已实现盈亏，点击日期查看当日交易 |
| 交易复盘 | 为交易填写策略、标签、执行评分和笔记，查看已复盘或待复盘交易 |
| 导入与数据 | 上传或拖放报告，重新扫描根目录，查看导入历史、解析提示和资金流水 |

点击一笔交易可打开详情并保存复盘。评分范围为 0—5，0 表示未评分；标签使用英文或中文逗号分隔，最多 20 个，每个不超过 40 字；笔记最多 10000 字。

侧边栏的“导出全部记录”会下载含复盘字段的 UTF-8 CSV，范围是数据库中的**全部账户和全部交易**，不受当前页面筛选条件影响。CSV 可用 Excel 打开，文本字段会进行必要的转义和公式防护。

## 导入 MT5 报告

在 MT5 历史页面选择所需时间范围，导出包含“持仓 / Positions”明细与账户信息的完整历史报告。可以使用以下任一方式导入：

1. 将报告放入本项目根目录，启动服务或点击“重新扫描并导入”。
2. 点击“导入交易”选择文件，或将文件拖放到导入区域。

支持 `.html`、`.htm`、`.xlsx`，支持中英文常见表头及 UTF-8 / UTF-16 报告。每个文件最大 **20 MB**，单次上传最多 **10 个文件**。根目录扫描只读取当前这一层，不扫描子目录，忽略 `index.html` 和图片等其他文件。

同一账户与持仓编号只保存一笔交易。HTML 和 XLSX 导出包含同一段历史时不会重复计数；已保存的复盘会保留。如果先导入未平仓记录，之后的报告提供了同一笔交易的平仓结果，系统会在开仓身份字段一致时更新为已平仓。已有平仓记录不会被旧的未平仓报告覆盖；其他核心字段冲突会保留现有数据并显示核对提示。仅来源文件或报表备注不同不会覆盖已有记录。

导入结果分别记录新增、更新和已存在的笔数；“已存在”包含完全重复及因冲突而保留旧值的记录，具体冲突见提示。服务重启时跳过文件名和内容均未变化的已导入报告。

若相同账户编号在报告中具有不同的非空服务器或币种，整份报告会被拒绝，以免混合不同账户数据。请核对报告来源后再导入；已有数据和复盘不会改变。

以下情况会明确提示错误或核对事项：

- 仅包含逐笔“成交 / Deals”或“订单 / Orders”的导出：当前不从成交自动重建持仓，请改用包含持仓的完整报告。
- `.xls`、`.csv`、截图和自定义表格：当前不作为 MT5 报告导入。
- 同一 XLSX 内包含多个交易报告工作表，或同一持仓编号包含不同的分拆记录：请分别导出清晰的持仓报告。
- 报告汇总与明细不一致，或成交表存在无法分配到持仓的额外费用：显示核对提示，不自行制造交易或分摊费用。

本系统读取历史导出文件，不连接 MT5 实时账户，也不执行下单。请保留原始报告；上传文件解析后不会另外保存一份原始文件副本。

## 统计口径

- **统计范围**：仅已平仓交易参与盈亏统计，各账户分别计算，金额使用该账户币种。
- **净盈亏**：报告中的盈利 + 佣金 + 隔夜利息 + 其他费用。费用保留报告原有正负号。
- **胜率**：净盈利交易数 ÷ 已平仓交易数；净盈亏为 0 的交易计入分母。
- **盈利因子**：所有净盈利之和 ÷ 所有净亏损之和的绝对值。
- **最大回撤**：按平仓时间排列，从所选交易的累计净盈亏曲线高点到后续低点的最大金额差。它不包含入金和出金，也不等同于持仓期间的浮动权益回撤。
- **日期**：筛选和日历以平仓日期为准，时间保留 MT5 经纪商报表原值，不推断或转换时区。“近 7 天 / 近 30 天”以该账户最后一笔交易日期为终点，方便查看历史报告。
- **资金流水**：入金、出金单独展示，不计入交易笔数、胜率或交易盈亏。

公开历史已移除私人账户报告、标识和基于实际交易的统计核对结果。保留的解析与统计样例使用明确合成的数据，不代表实际账户验证。示例报告文件名可使用 `ReportHistory-DEMO.html`；公开仓库不包含私人报告。

## 数据保存与备份

数据库保存在项目的 `data/trading.sqlite`，包含账户、交易、资金流水、导入历史和复盘笔记。数据不依赖浏览器缓存，刷新页面或重新启动服务不会丢失。

完整备份步骤：

1. 在运行服务的终端按 `Ctrl+C`，确保所有正在使用该数据库的服务均已停止。
2. 将整个 `data` 文件夹复制到独立的备份位置；同时按需保留原始 MT5 报告。
3. 恢复时先停止服务并备份现有 `data`，再将备份文件夹放回项目的 `data` 位置，重新启动。

SQLite 运行时可能产生 `trading.sqlite-wal` 和 `trading.sqlite-shm`。不要在服务运行中只复制主数据库文件，以免遗漏尚未合并的写入。CSV 用于查阅和外部分析，不包含完整数据库结构，当前也不支持将 CSV 作为恢复文件导入。

## 技术结构与检查

- 前端：Vue 3、TypeScript、Vite、Lucide 图标，SVG 累计盈亏图表。
- 后端：Node.js 22、Express、Multer，本地 HTTP API。
- 数据库：Node.js 内置 `node:sqlite`，使用 WAL 模式。
- 报告解析：Cheerio 读取 HTML，ExcelJS 读取 XLSX，JSZip 兼容 MT5 的 UTF-16 XML 文件。

```powershell
npm test
npm run build
npm audit
```

历史测试代码保留合成样例的报告格式与异常值、重复导入、未平仓到已平仓的更新、冲突报告保护、账户隔离、笔记持久化、上传限制和 CSV 导出。

`package.json` 将 ExcelJS 的间接依赖 `uuid` 固定到 `11.1.1`，以使用已修复的版本并保留 ExcelJS 所需的 CommonJS `v4()` 接口。上游修复说明见 [uuid 官方安全公告](https://github.com/uuidjs/uuid/security/advisories/GHSA-w5hq-g745-h8pq)。依赖更新后应重新运行上述检查。
