# TradeLog · 交易计划与订单记录

基于 Node.js、Vue 3、TypeScript 和 Element Plus 的本地交易记录应用。交易计划记录想法，交易订单记录实际执行；一份计划可关联多笔订单，订单也可以独立存在。数据保存在本机，不连接账户或下单。

## 启动

需要 **Node.js 22.13.0 或更高版本**，使用内置 SQLite，无需 Python 或其他数据库。在项目根目录执行：

```powershell
npm install
npm run dev
```

打开 [http://127.0.0.1:5173](http://127.0.0.1:5173)。开发命令同时启动 Vite 与端口 3001 的 API；前端端口被占用时以终端 Local 地址为准，先停止本项目已有服务以免后端冲突。

构建运行：

```powershell
npm run build
npm start
```

打开 [http://127.0.0.1:3001](http://127.0.0.1:3001)，前端和 API 由同一服务提供，仅监听本机。前端修改后重新构建，后端修改后重启，Ctrl+C 停止。Node.js 22 可能显示 SQLite ExperimentalWarning。

## 交易计划

填写品种、方向、周期、市场状态、关键结构、理由，以及选填的出场理由。品种支持搜索与自定义，输入后选择候选或按 Enter 确认。截图支持粘贴 / 上传 PNG、JPEG、WEBP，每份最多 4 张、每张 5 MB。

计划入场、止损、止盈选填，已填价格须为正数并符合方向；三项完整时显示按价格距离计算的收益 / 风险倍数，不含成本。原价位 OCR 可识别后填入，需自行核对，识别图不会自动保存为截图。

计划状态为草稿、待触发、未触发、取消、失效；待触发需完整品种、方向、周期和理由。取消原因可保留。旧版“已执行”显示为旧人工执行标记，不代表有真实成交。编辑正文保留状态，列表可按创建时间排序。

“关联订单”展示挂单、持仓、平仓、取消 / 失效数量；可为此计划录入订单，也可明确关联已有未关联订单。计划状态和订单状态分别管理，取消计划不会取消订单。

## 交易订单

从独立的“交易订单”入口录入，或从计划进入。当前按单账户使用，同一个订单号全局唯一；订单号按字符串保存，去除多余前导零，不损失长编号精度。同号事实归入同一订单，不自动跨计划转移。

- 挂单：填写挂单类型、目标价、挂单量，时间与有效期选填。
- 持仓：填写实际开仓价和成交量，开仓时间未知可留空。
- 已平仓：还需实际平仓价；时间、截图盈利和平仓原因可选填。可以直接补录平仓单，不虚构中间过程。
- 取消 / 失效：仅能手动明确结束已有挂单，不从截图缺失推断。

挂单字段与实际成交字段分别保存。时间按报告原时钟填写 `YYYY.MM.DD HH:mm:ss`，不猜测时区。截图盈利可能未含费用，不是净盈亏；未知盈利保留空，零仍是零，系统不猜币种、不汇总金额、不推算实际 R。

同号补录遇到品种、方向、成交量价或已确认平仓结果不同，会展示差异并拒绝覆盖。可补全未知信息，状态只明确前进，不支持分批成交自动拼单。订单详情可查看观察历史，与当前关联计划参数对比。

### 从 MT5 截图识别

选择挂单 / 持仓 / 已平仓模式，上传完整宽度的浅色表格或无表头数据行。识别只产生草稿，逐行选择并核对订单号、方向、数量、价位和时间后确认保存。当前市价和浮盈不作为平仓结果。

目前适配固定列布局，列顺序、缩放、语言、主题及裁剪变化可能造成识别缺失或错误；低置信度字段留空提示，可手动补录。识别图仅临时处理，不自动进入记录附件。此版本不扫描根目录、不导入 HTML / Excel / CSV 报告；历史报告导入模块已移除。

## 订单过程与复盘

每笔订单都有独立过程：价位调整、情绪、判断。三类分别保存，可添加文字和图片，每次最多 4 张、单张 5 MB。支持粘贴、预览和移除；价位允许保本 / 锁盈，情绪无需填写价格，不清空上次价位。失败时保留输入，相同操作重试不会重复追加。

有实际成交量和开仓价的持仓 / 平仓订单可填写复盘草稿，包含结果、是否按计划执行、交易判断、做得好的地方、下次改进和是否情绪化操作。只有已平仓订单可以完成复盘，且至少填写一项“做得好的地方”或“下次改进”。复盘不自动更改订单或计划状态。

未关联计划的订单同样可以记录过程和复盘。多页面编辑发生版本冲突时保留输入，先复制需要保留的文字，再明确重新读取整理。

各页签草稿独立保存，切换页签保留输入；读取、保存与识别在途暂时阻止切换。返回、换实体或换入口时确认未保存内容，刷新 / 关闭由浏览器提示。未保存内容不会写入数据库，导出也不包含这些草稿。

## 历史记录、导出与备份

旧计划的调整、来源快照、情绪和简单总结保留在“历史记录”，只读查阅。可核对后把旧过程组明确绑定到本计划的订单，保留原条目以便追溯；不会按编号自动迁移，也不会把旧计划总结变成订单复盘。

“导出数据”下载 `交易记录.zip`，内含 `交易计划.md`、`交易订单.md` 与 `images/`。包括全部已保存计划、独立订单（含未关联）、观察、过程及图片、复盘与历史来源，不受分页影响。解压整个 ZIP 并保留图片目录结构即可离线阅读。ZIP 不能导入恢复数据库。

数据在根目录 `data/trading.sqlite`。**升级、回退或恢复前，停止所有使用该库的服务并备份整个 data 文件夹**，包括可能存在的 WAL / SHM；不要只复制正在运行的主数据库。本次新增独立订单表，保留原计划、图片、旧业务表及隐藏字段，不批量重写旧数据、不删除旧表。旧版本不能完整读取新订单；需要回退数据时使用升级前一致备份，并另存当前完整数据。

旧独立报告复盘与模拟练习已经移除界面和服务，其历史数据仍留在数据库中，不纳入当前 Markdown 导出。本次开发没有打开、初始化或修改真实数据库。

## 工程说明

右上角可切换日夜主题，偏好保存在当前浏览器，业务数据不依赖浏览器缓存。模块、接口和约束见 [ARCHITECTURE.md](ARCHITECTURE.md)，进度见 [TASKS.md](TASKS.md)。OCR 使用 Sharp、Tesseract.js 与本地英文识别数据，JSZip 打包导出。

按当前要求不新增或运行测试，不做 API / OCR 试跑或浏览器验收。`npm run build` 只检查 TypeScript 并构建前端，不代表运行时行为或 OCR 准确率已验证。真实报告、截图、数据库与凭据不得提交到源码仓库。
