# TradeLog · 开仓计划

基于 Node.js、Vue 3 和 Element Plus 的本地开仓计划应用。记录品种、方向、分析周期、行情截图与入场想法，保存草稿或标记待执行。计划独立保存，无需连接外部服务。

## 启动

需要 **Node.js 22.13.0 或更高版本**。使用 Node.js 内置 SQLite，无需单独安装数据库或 Python。

在项目根目录运行：

```powershell
npm install
npm run dev
```

打开 [http://127.0.0.1:5173](http://127.0.0.1:5173)。此命令同时启动 Vue 开发页面和端口为 `3001` 的 API 服务，修改源码后自动更新。

如果 `5173` 已占用，Vite 会选择下一个可用端口，请以终端显示的 `Local` 地址为准。后端默认使用 `3001`，启动前请先停止本项目已运行的服务，避免重复占用。

构建后运行：

```powershell
npm run build
npm start
```

打开 [http://127.0.0.1:3001](http://127.0.0.1:3001)。此时前端和 API 由同一个 Node.js 服务提供；修改前端后需重新构建，修改后端后需重启服务。服务仅监听本机 `127.0.0.1`，在终端按 `Ctrl+C` 停止。Node.js 22 可能提示 SQLite 的 `ExperimentalWarning`，不代表启动失败。

## 记录计划

1. 点击“新建计划”，填写品种、做多 / 做空和分析周期。
2. 粘贴剪贴板图片，或选择文件上传。支持 **PNG、JPEG、WEBP**，每张最大 **5 MB**，每份计划最多 **4 张**。点击可放大查看，编辑时可移除。
3. 选择市场状态：上涨趋势、下跌趋势、震荡或不确定，按需记录关键结构和入场理由。
4. 按需填写计划入场价、止损价、止盈价，然后“保存草稿”或“标记待执行”。

草稿允许内容不完整；待执行至少需要品种、方向、分析周期和入场理由。截图、关键结构和价格均为选填。价格填写时必须是有效正数；做多时止损价低于入场价、止盈价高于入场价，做空则相反。三项价格完整且关系正确时，显示目标价格距离除以止损价格距离所得的计划收益 / 风险倍数，未计交易成本。

列表按创建时间从新到旧展示。点击计划可查看详情并继续编辑。计划及截图在点击保存后一起写入本地数据库，刷新页面或重启服务后仍会保留。

返回列表、点击品牌或“开仓计划”导航时，未保存的修改会触发居中的紧凑确认框；选择“继续编辑”、关闭或按 Esc 会保留编辑内容，只有确认“离开”才放弃修改。刷新或关闭页面时也会请求浏览器显示未保存提示。

## 导出 Markdown（含图片）

点击数据管理区的 **“导出数据”**，下载 `开仓计划.zip`，内容包括：

- `开仓计划.md`：UTF-8 Markdown，包含全部已保存计划的唯一标识、创建和更新时间、实际状态、品种、方向、周期、市场状态、关键结构、入场理由和计划价位，以及其他已保存内容。
- `images/`：全部已保存截图的原始文件，按计划顺序和截图顺序生成安全路径，例如 `images/plan-000001/image-01.png`。原始图片名记录在 Markdown 中，不参与压缩包路径生成。

导出包括草稿和待执行计划，不受列表分页影响。记录按创建时间降序排列，同一创建时间按唯一标识降序排列，截图按保存顺序排列。日期保留数据库中的 UTC 时间字符串；空字段标明“未填写”，不转换成零。中文、多行文字、反引号和其他特殊字符使用长度自适应的 Markdown 代码围栏原样保留。

**解压整个 ZIP 后再打开 Markdown**，并保留 `images` 文件夹的相对位置。图片链接使用相对路径，可在支持图片的 Markdown 阅读器中离线查看，无需运行本地服务。

导出使用已保存版本，不自动保存或丢弃正在编辑的内容，也不更新计划。没有已保存计划时显示提示；打包失败时不会下载部分或空压缩包。浏览器开始下载后，实际文件保存位置由浏览器设置决定。

## 数据保存与完整备份

继续使用项目中的 `data/trading.sqlite`，计划在 `plans` 表，截图以 BLOB 原始二进制保存在 `plan_images` 表。数据不依赖浏览器缓存。

完整备份方法：

1. 停止所有使用该数据库的服务。
2. 将整个 `data` 文件夹复制到独立的备份位置。
3. 恢复前先停止服务并备份当前 `data`，再放回备份文件夹并重启。

运行中可能存在 `trading.sqlite-wal` 和 `trading.sqlite-shm`。请停服后复制整个 `data` 文件夹，避免只复制主数据库而遗漏未合并的写入。Markdown ZIP 用于阅读和分享，目前没有从 ZIP 导入或恢复数据库的功能。

### 旧版本兼容

本次精简不重建或清空数据库，也不删除磁盘上的原始报告。已有计划编号、创建时间、分析内容与截图继续使用；旧交易数据留在原数据库中，但当前应用不再读取、展示或更新这些业务数据。

旧版计划的可空 `account_id` 列保留兼容：读取时忽略，保存时置空，接口不再输出或接受有效的账户关联。旧数据库中的父表及外键保持原状，不因删表破坏已有计划读写；新数据库只创建计划和截图表，不建立账户外键。无需执行破坏性迁移。

MT5 解析、导入、扫描、自动导入、交易页面、统计、复盘及旧 CSV 导出代码已从当前版本移除，旧模块专属测试一并移除。可以在 Git 提交 **`180d739`** 回看精简前的完整实现（包含取消计划账户关联的改动）；**`3f0efed`** 保留全站 Element Plus 版本。不要通过覆盖当前 `data` 的方式恢复旧代码。

## 技术结构

- 前端：Vue 3、TypeScript、Vite、Element Plus、Lucide 图标。
- `src/components/OpeningPlans.vue`：计划列表、新建、详情、编辑和截图交互。
- `src/components/AppNavigation.vue`：计划入口、Markdown 导出入口和使用说明。
- 后端：Express；Multer 仅用于计划截图上传，JSZip 用于 Markdown 与图片打包。
- `server/plans.mjs`：计划与图片存储、校验、HTTP API。
- `server/export.mjs`：Markdown 序列化与 ZIP 打包。
- `server/store.mjs`：打开现有 SQLite 数据库并初始化计划模块。

当前 API：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/plans` | 全部已保存计划 |
| POST | `/api/plans` | 保存新计划与截图 |
| GET | `/api/plans/:id` | 计划详情 |
| PUT | `/api/plans/:id` | 更新计划及保留 / 新增的截图 |
| GET | `/api/plans/:id/images/:imageId` | 查看原始截图 |
| GET | `/api/plans/export` | 下载全部已保存计划的 Markdown 与图片 ZIP |

计划保存使用 `multipart/form-data`，`payload` 字段为 JSON，`images` 字段为新增图片。编辑时通过 `keepImageIds` 指定保留截图。导出对记录与截图使用同一只读快照，完成打包后返回文件；空库返回明确提示。

本轮按用户要求**未新增或运行测试，也未运行浏览器验收**。`npm run build` 包含 TypeScript 检查与 Vite 生产构建，不代表功能测试。
