# TradeLog · 开仓计划、交易复盘与模拟练习

基于 Node.js、Vue 3 和 Element Plus 的本地交易记录应用。记录开仓计划和截图，手动导入 MT5 独立持仓、关联计划，并按计划完成复盘；“模拟练习”独立记录外部行情回放中的模拟交易。默认进入开仓计划，左侧可进入交易复盘或模拟练习。不连接交易账户，不下单，无需外部服务。

## 启动

需要 **Node.js 22.13.0 或更高版本**。使用 Node.js 内置 SQLite，无需单独安装数据库或 Python。

本次开发目录为 **`D:\code\vibecoding\TradingRecord-public`**。请从该目录启动；原 `TradingRecord` 是独立的历史工作目录，启动它不会加载本次改动。其他机器从实际克隆目录运行即可。每个目录使用各自的 `data`，应用不会自动复制另一目录的数据库、报告或截图。

```powershell
Set-Location D:\code\vibecoding\TradingRecord-public
npm install
npm run dev
```

打开 [http://127.0.0.1:5173](http://127.0.0.1:5173)。此命令同时启动 Vue 开发页面和端口为 `3001` 的 API 服务，修改源码后自动更新。

如果 `5173` 已占用，Vite 会选择下一个可用端口，请以终端显示的 `Local` 地址为准。后端默认使用 `3001`，启动前请先停止本项目已运行的服务，避免重复占用。

构建后运行：

```powershell
npm run build
npm start
```

打开 [http://127.0.0.1:3001](http://127.0.0.1:3001)。此时前端和 API 由同一个 Node.js 服务提供；修改前端后需重新构建，修改后端后需重启服务。服务仅监听本机 `127.0.0.1`，在终端按 `Ctrl+C` 停止。Node.js 22 可能提示 SQLite 的 `ExperimentalWarning`，不代表启动失败。

## 记录计划

1. 点击“新建计划”，填写品种、做多 / 做空和分析周期。
2. 粘贴剪贴板图片，或选择文件上传。支持 **PNG、JPEG、WEBP**，每张最大 **5 MB**，每份计划最多 **4 张**。点击可放大查看，编辑时可移除。
3. 选择市场状态：上涨趋势、下跌趋势、震荡或不确定，按需记录关键结构和入场理由。
4. 按需填写计划入场价、止损价、止盈价，然后“保存草稿”或“标记待执行”。

交易品种使用可输入、实时筛选的单选下拉框，支持代码（不区分大小写）和中文名称搜索。候选包含黄金、白银、主要外汇及交叉盘、原油、常见指数、比特币和以太坊的通用记录代码；实际经纪商代码可能不同。选择“代码 · 中文名称”候选时只保存代码，也可输入 `XAUUSDm` 等自定义代码并确认，不连接行情或交易账户。

每次新建默认 `XAUUSD`；编辑保留原品种，包括自定义代码与历史空值。使用清空按钮可清空后重新输入。选择候选或按 Enter 确认输入，Enter 在下拉框中只确认选项，不提交整份计划；未确认输入会阻止保存并显示提示，Esc 可取消本次输入、保留已选值。尚未确认的输入也纳入离开页面时的未保存保护。品种仍最多 40 个字符，自定义代码保留大小写，保存时沿用原有首尾空白处理。

草稿和已放弃允许内容不完整；待执行与已执行至少需要品种、方向、分析周期和入场理由。截图、关键结构和价格均为选填。价格填写时必须是有效正数；做多时止损价低于入场价、止盈价高于入场价，做空则相反。三项价格完整且关系正确时，显示目标价格距离除以止损价格距离所得的计划收益 / 风险倍数，未计交易成本。

列表默认按创建时间从新到旧展示。点击“创建时间”表头，在最新优先和最早优先之间切换，箭头显示当前方向；切换时先对全部计划排序，再分页并返回第一页。排序使用原始创建时间，同一时间按唯一标识稳定排列。重新加载列表或编辑后返回时保留当前方向，重新打开应用默认最新优先。编辑不会改变创建时间及同一排序方向下的相对位置，Markdown 导出仍按固定的创建时间降序排列。

点击计划可查看详情并继续编辑。新建保留“保存草稿 / 标记待执行”；编辑已有计划只有“保存修改”，包括按回车提交时也保留其当前状态。计划及截图在点击保存后一起写入本地数据库，刷新页面或重启服务后仍会保留。

返回列表、点击品牌或“开仓计划”导航时，未保存的修改会触发居中的紧凑确认框；选择“继续编辑”、关闭或按 Esc 会保留编辑内容，只有确认“离开”才放弃修改。刷新或关闭页面时也会请求浏览器显示未保存提示。

## 更改状态

点击列表状态列或只读详情中的当前状态标签，会弹出紧凑横向选择条，按“草稿、待执行、已执行、已放弃”固定顺序一行排列。当前状态用浅色背景和小勾标记，点击当前项不重复提交，选择其他状态即可更改，也可改回纠正误操作。选择条始终以实际保存状态为准，失败或取消放弃不改变选中项。状态列与操作列居中，操作列仅保留“查看”；点击状态标签或浮层选项不会打开详情。

状态标签支持 Tab 聚焦、Enter / Space 打开，选择条支持方向键或 Enter / Space 选择；点击外部或按 Esc 关闭。标签保留原有颜色、下拉箭头、悬停与焦点提示；提交期间显示忙碌状态并禁止重复操作，更新或离开列表时关闭浮层。

| 状态 | 含义 |
| --- | --- |
| 草稿（draft） | 想法未整理完 |
| 待执行（ready） | 等待入场条件 |
| 已执行（executed） | 已实际开仓，不代表已平仓 |
| 已放弃（abandoned） | 决定不执行 |

从不完整草稿直接改为待执行或已执行时，服务端会检查基础字段，缺项则提示先编辑补齐；失败不会改变状态。状态操作不会重传分析内容或截图，保存中禁止重复提交。

标记已放弃时弹出紧凑确认框，原因选填，最多 2000 字，取消不修改状态。改回其他状态时保留原因，并在详情与导出中标为“上次放弃原因”；再次放弃时会预填旧原因，可编辑或清空。不记录复杂状态历史。

`statusChangedAt` 仅在实际状态切换时写入服务端时间。新计划首次切换前和历史记录缺少该字段时显示“未记录”，不从创建 / 更新时间推测历史。普通内容保存、同状态重复请求都不改写此时间，状态操作也不改变创建时间。编辑表单不提交状态、原因或状态变更时间，后端会在事务中保留数据库的最新状态及相关信息，避免旧表单覆盖较新的状态；若最新状态为待执行或已执行，编辑内容也需符合相应基础要求。

## 交易复盘

1. 进入“交易复盘”，点击右上角 **导入 MT5 报告**，手动选择 HTML、HTM 或 XLSX。完成后留在复盘页，查看新增、更新、重复、冲突、不完整记录数量及解析提示。
2. 在“待关联交易”按品种、来源账户或开仓日期筛选，勾选 1 至 100 个持仓。可同时显示已关联持仓，其复选框禁用，可进入原计划核对。
3. 点击“关联到开仓计划”，按创建时间、品种、方向、入场理由搜索并选择计划，核对完整理由。每个持仓可手动选择“未分类 / 首次入场 / 加仓 / 重新入场”及备注，默认未分类，不根据时间或金额自动推断。
4. 确认后进入复盘详情，依次查看原计划、实际执行、复盘总结。“是否遵守原计划”为未评定、是、部分遵守或否；可保存草稿，至少填写“做得好的地方”或“下次改进”之一，且仍有关联持仓，才能完成复盘。已完成复盘可以继续编辑。
5. 实际执行列表中可以修改用途、备注、解除关联或明确更换计划。解除只移除关联，保留持仓和总结；持仓回到待关联列表。更换计划会同时更新原计划与目标计划。批量关联有任何冲突则整批回滚，不会悄悄抢占其他计划的持仓。

**看板口径**：待关联是持仓数量，待复盘和已复盘是计划数量；所有卡片覆盖全部来源，不受列表筛选影响。只有至少关联一个持仓的计划进入复盘队列，同一计划无论关联多少个持仓都只算一份。计划的草稿 / 待执行 / 已执行 / 已放弃状态与复盘状态独立，关联、导入和复盘都不自动改写计划状态、分析或价位。

**复盘更新**：已复盘计划新增、解除、更换关联，修改用途 / 备注，或收到较新报告的持仓结果变化时，标记“有更新待补充”，回到待复盘列表，保留原文字及上次完成时间。相同数据重复导入不会重新打开复盘。最后一个关联解除后该计划暂离开队列，原总结仍保留，在计划详情的“实际交易与复盘”入口可以查看。

跨页面、返回列表时会提示未保存的计划或复盘文字；取消则保留输入。复盘保存校验服务端版本，其他页面发生关联、结果或总结变化时拒绝覆盖，当前输入保留。请先复制需要保留的文字，再点击“刷新资料”核对最新版本。此处只记录最后完成时间，不建立复杂的版本历史。

### 支持的 MT5 报告与边界

- 复用脱敏历史中的 HTML / XLSX 解析器，支持中英文完整历史报告，以及 UTF-8 / UTF-16 HTML 和含 UTF-16 XML 的 XLSX。每份文件最多 25 MB，XLSX 解压内容最多 100 MB / 5000 个条目，表格最多 20 万行、200 列，单份最多 2 万个持仓。报告上传与原有截图上传分别限流和校验，不共用截图字段或大小限制。
- 要求报告注明 **Hedge / 对冲模式**，同时具备公司、服务器、账户编号、账户币种、报告日期；持仓表须有稳定持仓编号，以及开仓 / 平仓时间和价位双列、品种、方向、交易量、盈利列。不会猜测缺失的账户身份或模式。
- 以“公司 + 服务器 + 账户编号”的规范化组合区分来源，再与持仓编号组成唯一键；同号但不同服务器 / 公司的持仓互不覆盖。同一来源的币种变化被拒绝。计划本身没有绑定交易账户，可手动关联来自不同账户的持仓。
- 一行代表一个独立持仓。文件内同一持仓编号多次出现、多个持仓分区、无法区分的分批平仓 / 拆分交易量、净额持仓合并格式均拒绝整份导入，不从订单或逐笔成交拼装持仓。不要手动删行凑成可导入格式，应从 MT5 重新导出可识别的完整持仓报告。
- 当前仅导入“持仓历史”中具有开平仓双列的记录；单独的“未平仓持仓 / Open Positions”分区暂不导入并给出提示。仅有订单 / 成交表的报告不能导入。历史表内缺少平仓时间的持仓标为未平仓，保留其客观信息，不计入已实现净额。
- 同一唯一键重复导入不新增。较新报告可更新平仓结果及报告止损止盈等客观字段；开仓时间、开仓价、方向、品种或交易量不同的记录视为冲突，防止把分拆持仓误当更新。日期相同 / 更早但内容不同、完整平仓退回未平仓或不完整，也不会覆盖。此类冲突逐个报告，其他可识别记录仍可导入；关联和复盘文字始终保留。
- 报告时间沿用经纪商服务器时钟，不假设 UTC、不转换为本机时区；筛选日期也是该时钟的开仓日期。计划与复盘创建 / 完成时间为应用保存的 UTC，界面显示为浏览器本地时间。

### 盈亏口径

持仓净额为报告行中的 **盈利 + 手续费 + 库存费 + 其他费用**，保留报告原正负号。缺少平仓价、盈利、手续费或库存费时标为信息不完整；没有单独费用列通常表示无该项费用，但成交表存在无法分配的额外费用时相关平仓也标为不完整。未平仓或不完整记录的已实现净额为空值，不按零收益交易处理。缺失值不会伪造为完整平仓。

入金、出金、信用等资金流水和汇总行不生成持仓，不计入交易盈利。报告汇总笔数或净额不一致会提示核对，不根据汇总反推或摊分持仓结果。界面及导出按**来源账户与币种**分别汇总，不跨币种求和，也不换算账户收益率。账户级独立费用不擅自分摊，因此此处是持仓结果，不是账户余额对账。

报告中的 SL / TP 只作为“报告止损 / 止盈”展示，不是最初止损止盈，不能拿它推断原始风险或 R 倍数。原计划价位与实际成交资料分别保存。上传后仅持久化解析结果、来源和文件名，不保存原报告文件，请自行保留原件。

## 模拟练习：纯手工记录与统计

在外部工具回放 K 线，然后在本系统手工填写模拟记录。**没有行情接入、K 线播放器、虚拟撮合、练习场次、任务、课程或父计划流程**。模拟数据与真实计划、MT5 持仓和真实复盘各自独立，不能通过 MT5 导入模拟记录。

进入“模拟练习”默认看到看板，内部三个页签共用同一批持久化记录：

1. **看板**：按全部模拟记录查看已平仓笔数和待复盘笔数；有有效历史盈亏时再单独按币种显示财务统计。空状态可直接新建记录。
2. **交易记录**：直接新建、查看、编辑同一条模拟记录；按真实创建时间最新 / 最早排序，或按草稿 / 模拟持仓中 / 已平仓筛选。不提供删除或批量清空。
3. **复盘**：只列已平仓的同一批模拟记录，可筛待复盘（含待补充）、已复盘或全部已平仓。打开详情核对原分析、截图和已保留的历史资料，再补充总结；不会复制成另一条记录。

### 记录字段与状态

品种默认 `XAUUSD`，复用可搜索 / 自定义品种选择器。表单保留记录状态、品种、方向、分析周期，以及选填的市场状态、关键结构、开仓分析、计划止损 / 止盈与截图。

**暂时移除整块“模拟开平仓”表单**：模拟开仓时间、开仓价、仓位 / 手数、模拟平仓时间、平仓价、净盈亏（含费用）、币种，不折叠或转移到其他录入入口。新建缺失的数值与行情时间保存为 `null`，币种为空字符串，不默认 USD、不生成当前行情时间或零盈亏。

| 状态 | 最低要求 |
| --- | --- |
| 草稿 `draft` | 可保存不完整内容；已填计划止损 / 止盈仍须为正数 |
| 模拟持仓中 `open` | 品种、方向、分析周期 |
| 已平仓 `closed` | 品种、方向、分析周期；无需开平仓时间、价格、净盈亏或币种 |

数据库保留兼容字段，不做破坏性迁移。编辑时前端只提交可见内容；服务端在事务中读取原记录，原样保留隐藏的时间、价位、仓位、净盈亏和币种，包括明确的 `0`。旧客户端即使提交这些隐藏字段，也不会覆盖已有值或填入新记录。不会因为历史隐藏字段缺失而阻止状态保存。详情和导出保留历史值，缺失不变成零。

系统仍另行记录真实 UTC `createdAt` / `updatedAt`，不拿创建时间冒充回放行情时间；历史行情时间不作时区转换。可见的计划止损 / 止盈仍校验正数、有限性及一万亿上限，不据此计算或补造盈亏。

截图共用一套附件，可标记“开仓前”或“复盘”。支持粘贴 / 上传 / 放大 / 移除，PNG、JPEG、WebP，每张不超过 5 MB、每条最多 4 张。复盘阶段通过“编辑记录 / 截图”补充附件并选择用途；附件随记录事务保存为独立模拟图片表中的原始 BLOB，刷新或重启不会丢失。

### 模拟看板口径

状态与复盘进度按**全部模拟记录**统计，交易列表和复盘列表不按币种隐藏记录，因此无币种的新记录始终可查看和复盘：

- 已平仓笔数：全部手动状态为已平仓的记录数，允许没有盈亏结果。
- 待复盘笔数：全部已平仓且复盘未完成（含待补充）的记录数。
- 历史盈亏区：仅使用已平仓、净盈亏是明确有限数值、且币种非空的历史记录。币种筛选仅影响这一区，不影响上面的状态计数或列表。
- 历史胜率 = 同币种净盈利样本数 / 同币种有效盈亏样本数；明确填过的 0 是持平并计入分母，缺失结果或币种的记录既不算持平 / 亏损，也不进入分母。
- 累计净盈亏和盈利 / 亏损 / 持平笔数均来自同一批同币种有效样本，不混加不同币种。
- 没有有效结果时显示“暂无盈亏数据”，不把未知结果显示为 0 金额或 0% 胜率，也不新增盈亏录入入口。

例如四笔虚构已平仓记录中，三笔已有 USD 结果 `+20、-10、0`，第四笔没有盈亏：已平仓计数是 4，USD 财务区有效样本是 3，胜率约 33.3%、净盈亏 +10 USD。第四笔仍进入复盘队列但不参与财务统计。示例不会写入数据库。指标始终由持久化记录派生，不保存重复计数。

### 模拟复盘与编辑保护

每条记录保留“是否按自己的分析执行：未评价 / 是 / 部分 / 否”、“做得好的地方”、“问题与改进”。已平仓后可保存复盘草稿；完成复盘至少要有一项非空文字总结，并记录完成时间。

已完成复盘之后，修改交易事实、状态、分析或截图会标记**待补充**，保留总结和上次完成时间；保存没有实际变化的记录不重新打开复盘。状态退回草稿 / 模拟持仓中后，该记录不参与已平仓统计与复盘队列，旧总结仍可在详情中查看。之后重新标记已平仓需再核对总结。

交易内容与复盘分别使用 `recordRevision` / `reviewRevision`。内容保存只更新事实与附件并保留数据库最新复盘；复盘保存只更新总结并核对两个版本，不覆盖内容或图片。过期页面保存时提示冲突并保留输入，请复制需保留的文字后“重新读取”最新版本。保存中禁止重复提交，返回、导航、重新读取和浏览器刷新沿用未保存保护。记录保存后，同一记录的列表、看板和复盘状态同步更新；其他窗口的数据可手动刷新读取。

## 导出 Markdown（含图片）

点击数据管理区的 **“导出数据”**，下载 `开仓计划.zip`，内容包括：

- `开仓计划.md`：UTF-8 Markdown，包含全部已保存计划的唯一标识、创建和更新时间、实际状态、状态变更时间、放弃原因、品种、方向、周期、市场状态、关键结构、入场理由和计划价位；附上每份计划已关联持仓、来源账户及币种分组净额、用途备注、复盘状态、总结和上次完成时间。
- `images/`：全部已保存截图的原始文件，按计划顺序和截图顺序生成安全路径，例如 `images/plan-000001/image-01.png`。原始图片名记录在 Markdown 中，不参与压缩包路径生成。
- 有模拟记录时追加 `模拟练习.md` 与 `practice-images/`：包含全部已保存模拟记录的状态、回放时间、实际创建 / 更新时间、币种、手填盈亏、分析、复盘及原始截图。与真实计划分别成文，不混算金额，也不受模拟币种 / 状态 / 页签筛选影响。

导出包含全部四种状态的计划，不受列表分页或排序选择影响。记录按创建时间降序排列，同一创建时间按唯一标识降序排列，截图按保存顺序排列。日期保留数据库中的 UTC 时间字符串；缺失的状态变更时间显示“未记录”，其余空字段标明“未填写”，不转换成零。已放弃计划显示“放弃原因”，其他状态有保留原因时显示“上次放弃原因”。中文、多行文字、反引号和其他特殊字符使用长度自适应的 Markdown 代码围栏原样保留。

**解压整个 ZIP 后再打开 Markdown**，并保留 `images` 文件夹的相对位置。图片链接使用相对路径，可在支持图片的 Markdown 阅读器中离线查看，无需运行本地服务。

导出使用已保存版本，不自动保存或丢弃正在编辑的内容，也不更新计划或模拟记录。真实计划为空但存在模拟记录时仍可导出；两类记录均为空时显示提示。打包失败时不会下载部分或空压缩包。浏览器开始下载后，实际文件保存位置由浏览器设置决定。

## 数据保存与完整备份

继续使用当前开发目录中的 `data/trading.sqlite`，计划在 `plans` 表，截图以 BLOB 原始二进制保存在 `plan_images` 表。复盘使用 `tr_review_accounts_v1`、`tr_review_positions_v1`、`tr_review_links_v1`、`tr_review_summaries_v1` 四张独立命名的表，包含来源账户、持仓、唯一关联和总结。数据不依赖浏览器缓存。

完整备份方法：

1. 停止所有使用该数据库的服务。
2. 将整个 `data` 文件夹复制到独立的备份位置。
3. 恢复前先停止服务并备份当前 `data`，再放回备份文件夹并重启。

模拟记录另用 `tr_practice_records_v1` 保存内容、复盘和各自版本，`tr_practice_images_v1` 保存模拟附件；不关联真实计划 / 持仓，不修改旧模块数据表。启动时检查模拟表的列、主键和外键，结构不兼容会报错停止，不覆盖或清空。导出会与真实计划、截图一起读取同一个 SQLite 快照，文档与图片目录彼此独立。

运行中可能存在 `trading.sqlite-wal` 和 `trading.sqlite-shm`。请停服后复制整个 `data` 文件夹，避免只复制主数据库而遗漏未合并的写入。**Markdown ZIP 包含计划及已关联资料和全部模拟记录，但不包含未关联真实持仓，不是完整备份**，目前没有从 ZIP 导入或恢复数据库的功能。原报告另外保管。

## 技术结构

- 前端：Vue 3、TypeScript、Vite、Element Plus、Lucide 图标。
- `src/components/OpeningPlans.vue`：计划列表、新建、详情、编辑和截图交互。
- `src/components/AppNavigation.vue`：计划、交易复盘、Markdown 导出入口和使用说明。
- `ReviewWorkspace.vue`、`ReviewDetail.vue`、`ExecutionTable.vue`、`LinkPositionsDialog.vue`、`PlanReviewEntry.vue`：复盘看板、详情、持仓列表、关联窗口和计划内入口；`src/reviews/` 保存共享类型与请求逻辑。
- 后端：Express；Multer 分别处理计划截图和 MT5 报告；Cheerio / ExcelJS 解析 HTML / XLSX；JSZip 用于 XLSX 字符编码适配和 Markdown 图片打包。
- `server/plans.mjs`：计划与图片存储、校验、HTTP API。
- `server/export.mjs`：Markdown 序列化与 ZIP 打包。
- `server/store.mjs`：打开现有 SQLite 数据库并初始化计划及复盘模块。
- `server/review-parser.mjs`：报告结构和数据解析；`review-store.mjs`：来源唯一性、幂等导入、事务关联、复盘状态；`review-routes.mjs`：报告上传与复盘 API。
- `server/practice.mjs`：模拟记录校验、版本保护、持久化和 API；`practice-export.mjs`：独立模拟 Markdown 及图片追加导出。只复用既有截图校验函数，不调用 MT5 解析器。
- `PracticeWorkspace.vue`、`PracticeRecord.vue`、`PracticeImages.vue`：模拟看板与页签、单条记录与复盘、共用附件交互；`src/practice.ts` 定义模拟数据类型及派生统计。

计划保存使用 `multipart/form-data`，`payload` 字段为 JSON，`images` 字段为新增图片。新建仅支持草稿和待执行；编辑时通过 `keepImageIds` 指定保留截图，旧客户端即使提交其他合法状态也不覆盖数据库当前状态。状态更新使用 JSON，仅接受 `status`，及目标为 `abandoned` 时的选填 `abandonReason`；返回 `{ plan, changed }`，同状态请求为只读返回。原因省略时保留上次值，空字符串可清空；状态变更时间始终由服务端维护。导出对记录与截图使用同一只读快照，完成打包后返回文件；空库返回明确提示。

关联和复盘接口使用 JSON。关联由服务端约束每个持仓最多归属一个计划，修改 / 解除需携带原 `planId`，更换需明确 `fromPlanId` 与 `toPlanId`。复盘 `expectedRevision` 用于防止过时页面覆盖；任何关联、结果和总结的实际更改都会推进版本。计划、截图及关联复盘从同一个数据库只读快照导出。

模拟内容接口的 `payload` 只更新可见模拟字段，隐藏开平仓字段由服务端保留旧值，`keepImages` 声明保留附件及用途，`newImagePurposes` 按上传顺序标注新增附件；不接收真实计划或持仓关联，也不从旧内容表单覆盖复盘。复盘接口仅更新总结，不触碰图片。没有删除 / 批量清空接口。

本轮按用户要求**未新增或运行测试，未做接口功能验证或浏览器验收**。`npm run build` 只包含 TypeScript 检查与 Vite 生产构建，不代表功能测试；功能由用户自行验证。未往真实库填写示例数据。报告、账户数据、数据库和截图不会纳入源码仓库。请从本文指定的 `TradingRecord-public` 目录重启 `npm run dev` 试用，本轮代码仅在公开副本独立提交，不自动推送。
