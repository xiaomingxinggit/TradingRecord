# TradeLog · 计划、持仓过程与复盘

基于 Node.js、Vue 3、TypeScript 和 Element Plus 的本地交易记录应用。一份计划包含开仓计划、持仓过程与简单交易复盘，使用同一份记录。数据保存在本机，不连接交易账户或下单。

## 启动

需要 **Node.js 22.13.0 或更高版本**，使用 Node.js 内置 SQLite，无需安装 Python 或其他数据库。

在项目根目录运行：

```powershell
npm install
npm run dev
```

打开 [http://127.0.0.1:5173](http://127.0.0.1:5173)。开发命令同时启动 Vite 和端口 3001 的 API。如果 5173 被占用，以终端显示的 Local 地址为准；启动前停止本项目已运行的服务，避免后端端口冲突。

构建后运行：

```powershell
npm run build
npm start
```

打开 [http://127.0.0.1:3001](http://127.0.0.1:3001)。前端与 API 由同一 Node.js 服务提供，仅监听本机 127.0.0.1。修改前端后重新构建，修改后端后重启服务，按 Ctrl+C 停止。Node.js 22 可能显示 SQLite ExperimentalWarning。

## 开仓计划

1. 新建计划，填写品种、方向、分析周期、市场状态、关键结构和入场理由。品种默认 XAUUSD，支持搜索与自定义代码；选择候选或按 Enter 确认输入。
2. 粘贴或上传 PNG、JPEG、WEBP 截图，每张最多 5 MB、每份计划最多 4 张。点击放大，编辑时可移除，截图随正文保存。
3. 计划入场价、止损价、止盈价选填，填写时为正数并符合交易方向。三项完整时显示按价格距离计算的收益 / 风险倍数，不含交易成本。
4. 价位 OCR 使用本地识别。单行可直接填入，多行需选择一行；核对后保存。识别图片不会自动变成计划截图。
5. 保存草稿可稍后补全；待执行或已执行需要品种、方向、周期和入场理由。

列表默认最新创建优先，点击“创建时间”切换排序，作用于全部计划并回到第一页。编辑不改变创建时间。

计划状态独立保存：草稿、待执行、已执行、已放弃。已执行表示已经开仓，不代表平仓或复盘完成。通过列表或详情的状态标签切换；放弃原因选填，切回其他状态后保留上次原因。正文保存保留当前状态，只有实际切换状态才更新状态变更时间。

## 持仓过程

保存计划后进入“持仓过程”。选择已有持仓组追加价位，或填写手动持仓编号新建独立组。相同编号不会自动合并，不会猜测账户归属。

每次价位记录包含选填参考入场价、本次止损、本次止盈和调整原因，时间由服务端记录。空止损 / 止盈表示本次未设置；允许保本和锁盈，不套用开仓计划的价格关系，也不修改原计划价位。OCR 只填入当前目标组的草稿，识别期间锁定目标，编号须手动核对。

情绪可以单独保存：选择平静、焦虑、恐惧、贪婪、急躁或其他，备注和关联持仓组选填。情绪事件与价位记录分别展示，不需要任何价格，不会清空上一次价位，也不清空未保存的价位草稿。

追加失败或超时会保留输入。保持相同内容重试使用同一请求编号，服务端防止重复追加；修改内容后会视为新操作。历史来源快照保留，原有来源组可以继续追加。

## 简单交易复盘

同一计划的“交易复盘”包含四项：

- 交易结果：未记录、未结束、盈利、亏损、持平。
- 是否按计划执行：未评定、是、部分、否。
- 做得好的地方。
- 下次改进。

支持保存草稿和完成复盘；完成前至少写一项文字总结，交易结果可以未记录。复盘不计算金额、盈亏统计或胜率，也不自动更改计划状态。

多页面同时编辑时，独立版本检查阻止旧复盘覆盖新内容。发生冲突会保留输入，请先复制需要保留的文字，再重新读取最新版本后整理。

## 草稿与保存

三个部分各自保存。切换页签保留所有草稿，并在页签显示未保存提示；保存一个部分不会保存或清空另一个部分。读取、保存和 OCR 期间阻止切换；返回列表统一确认未保存内容，刷新或关闭页面使用浏览器的离开提示。未保存内容没有写入数据库。

## 导出与完整备份

“导出数据”下载 `开仓计划.zip`，包含 UTF-8 的 `开仓计划.md` 和 `images/` 原始截图。每份计划导出开仓内容、持仓价位历史及来源快照、情绪事件、简单复盘。所有状态的已保存计划均导出，不受分页或当前页签影响；不保存正在编辑的内容，不输出内部幂等元数据。

解压整个 ZIP 后打开 Markdown，保留图片相对目录即可离线阅读。ZIP 是阅读资料，不是完整数据库备份，目前不能从 ZIP 导入恢复。

数据在根目录 `data/trading.sqlite`。完整备份请停止所有使用该库的服务，复制整个 `data` 文件夹；恢复前同样停服并备份当前目录。运行时可能存在 WAL / SHM 文件，不要只复制正在使用的主数据库。

### 历史兼容

本次重构移除了旧独立 MT5 报告导入 / 关联 / 复盘和模拟练习的界面及服务代码，**不删除真实历史表或记录**。这些旧业务不再展示或加入 Markdown 导出，可用完整数据库备份另行恢复。不会扫描根目录或导入报告。

已有计划、截图、状态和持仓调整继续使用；缺失的情绪与简单复盘视为空，不补造历史时间，不批量重写数据库。原持仓来源快照保留为历史信息，追加不再依赖旧关联服务。

计划的旧可空 `account_id` 列及数据库既有父表保持原状；读时忽略旧账户字段，计划写入时仍沿用置空逻辑。新业务字段保存在原计划 JSON 内，无需破坏性迁移。旧库恢复和版本回退应先停服并做好完整备份，不使用新建空库替代。
